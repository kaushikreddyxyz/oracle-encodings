## Model architecture (the synthetic Othello-GPT)

| Property            | Value                                              | Notes |
|---------------------|----------------------------------------------------|-------|
| Architecture        | GPT-2 style, decoder-only, autoregressive          | Built on minGPT (Karpathy) |
| Layers              | 8                                                  | |
| d_model (residual)  | 512                                                | |
| Attention heads     | 8                                                  | → head dim 64 |
| MLP                 | 4× ratio → d_mlp = 2048 **[UNVERIFIED exact, standard GPT-2 convention]** | |
| Context length      | 60                                                 | One full game |
| Vocab size          | 61                                                 | See vocab below |
| Params              | ~25M                                               | |
| Dropout (original)  | **attention + residual dropout ON**                | Inherited from GPT-2/minGPT. See gotchas. |
| Activation          | GELU **[UNVERIFIED, GPT-2 default]**               | |

**Vocabulary (size 61) — exact construction:**
- Token `0` = **pass** (special token).
- Tokens `1`–`60` = the 60 **playable** board squares.
- The **4 center squares** (filled at game start, never playable) are **excluded** from
  the vocab. This is the source of the 64-vs-60 off-by-one (see conventions file).

**Input/target convention:** games are length 60; model receives the first 59 moves
(`tokens[0:-1]`) and predicts moves `tokens[1:]`. Standard teacher-forced next-token
prediction. Objective is **legal** moves, not good moves.

**Training data:** *synthetic* dataset = games generated by choosing a uniformly-random
**legal** move at each step. (A separate "championship" dataset of real human games also
exists — it produces a measurably different model with a worse world model. The linear
representation result is established on the **synthetic** model. Use synthetic unless you
have a specific reason not to.)

## The representation (what's in the residual stream)

- Board state is **fully computed by ~layer 4**, then *used* by layers 5–6 for downstream
  legal-move computation. (Nanda probed layer 6 but the info is present and interventable
  from layer 4.)
- Dimension budget: of 512 residual dims, ~**64** encode "which cell is my-colour" + ~**60**
  encode "which cell is blank" (centers never blank) ≈ **124 dims** (~25% of the stream)
  devoted to the world model. Roughly **2 directions per cell**.
- Per-cell probe is **3-way** (blank / black / white). Softmax translation-invariance means
  the 3 logits carry only **2** meaningful directions per cell.

## Probe — Nanda's exact setup (known-good reference values)

These are the values from Nanda's blog write-up. They are a *known-good anchor*, not a
prescription.

| Probe hyperparam        | Value                                                |
|-------------------------|------------------------------------------------------|
| Probe type              | Linear — plain (multinomial) logistic regression     |
| Structure               | ~60 cells × 3-way classifier, shared residual input  |
| Trained on activation   | `resid_post` of layer 6 → `get_act_name("resid_post", 6)` |
| Optimizer               | `AdamW`                                               |
| Learning rate           | `1e-4`                                                |
| Weight decay            | `1e-2`                                                |
| eps                     | `1e-8`                                                |
| betas                   | `(0.9, 0.99)`                                         |
| Move range trained on   | `[5:-5]` (skip first/last 5 moves)                   |
| Training data volume    | ~4 million synthetic games (Nanda notes far fewer suffice) |
| Parity handling         | Separate probes trained on **even**, **odd**, and **all** moves |

**The 3→2 direction conversion (for black-to-play probe):**
```
my_probe    = black_dir - white_dir
blank_probe = blank_dir - 0.5 * black_dir - 0.5 * white_dir   # the 0.5 is admittedly unprincipled but worked
# third dimension discarded (softmax translation invariance)
# both normalized to unit vectors (norm only affects probe confidence, not accuracy)
```

**Reference accuracy (the known-good anchor to self-check against):**
- Li et al. **linear** probe: ~**20.4% error** (looked like failure).
- Li et al. **non-linear** (2-layer ReLU MLP) probe: ~**1.7% error**.
- Nanda **linear** probe in mine/theirs frame: **high-90s % accuracy** on the middle band
  of moves (worse on corners). Odd↔even transfer near-perfect after flipping.
- Accuracy figures are scored on the **middle band of moves only** (the `[5:-5]` range),
  over ~100 games (~5000 moves) in Nanda's reporting.

**Intervention (causal) reference:** negate the coordinate along `my_probe` for a cell in
the residual stream after **layer 4** (sometimes layer 3), optionally scaled by a factor
(`scale` ranged 0–16). Single-cell flips work well; multi-cell is jankier. Edits don't
perfectly recover logit magnitudes (partly attributable to dropout-induced redundancy).

## Loading the model in TransformerLens — and the v3.0 LANDMINE

**⚠️ READ THIS — it will silently corrupt results if ignored. Cross-ref `05_gotchas.md`.**

- The pretrained synthetic model is hosted on HuggingFace under
  **`NeelNanda/Othello-GPT-Transformer-Lens`** (the championship variant is
  `championship_model.pth` in the same place; the synthetic model is the default the demo
  loads).
- **All existing Othello-GPT code** (Nanda's notebook, Andrew Lee's probe code, ARENA
  material) is written against the legacy **`HookedTransformer.from_pretrained(...)`** API.
- **TransformerLens 3.0 deprecated `HookedTransformer`** in favor of **`TransformerBridge`**.
  Legacy `HookedTransformer` still works on the 3.x branch via a compatibility layer, but:
- **The numerics default changed.** New default ("bridge") preserves raw HuggingFace
  weights, so logits/activations match HF — **NOT** the legacy `HookedTransformer`, which
  by default **folds LayerNorm and centers weights**. Call
  **`bridge.enable_compatibility_mode()`** to get HookedTransformer-equivalent numerics.
- **Why this matters for Othello specifically:** the published probe directions, the
  "board state fully computed by layer 4" finding, and the residual-stream geometry are all
  in the **LayerNorm-folded, weight-centered** frame. If you load weights in the new default
  frame, you are probing a *different numeric representation* than every published result,
  and your geometry/accuracy will silently disagree with the literature with no error.

**Safe options (pick one and pin it explicitly):**
1. **Pin a pre-3.0 TransformerLens** (e.g. install a 2.x release) so `HookedTransformer`
   with its LayerNorm-folding default is the native path. Most existing code "just works."
2. **Use 3.x but force compatibility:** load via the bridge and call
   `enable_compatibility_mode()`, OR use the still-present legacy `HookedTransformer`
   path, and verify numerics.
3. Whichever you choose, **record the exact installed version** in your run log, and
   **sanity-check** by reproducing a known number (e.g. probe accuracy in the high-90s on
   middle moves) before building anything on top.

- Install (legacy): `pip install git+https://github.com/neelnanda-io/TransformerLens`
  (add `@<tag>` to pin). The repo now lives under `TransformerLensOrg/TransformerLens`.
- The demo notebook disables autograd (`torch.set_grad_enabled(False)`) for inference to
  save memory — fine for probing/analysis, but remember to re-enable it if you train
  anything.

## Compute envelope

- Loading + probing the pretrained model: trivial, runs on a single consumer GPU or even
  Colab T4; probe training is minutes.
- Training Othello-GPT from scratch: the *original* default config was set up for 8 GPUs
  (~12 GB each) — that's the authors' setup, **not** a hard floor. The 8L/512 model trains
  fine on one consumer GPU with reduced batch size / gradient accumulation; expect
  hours-scale wall-clock. Data is synthetic and CPU-cheap to generate (legal-move
  enumeration), so there's no dataset-download bottleneck.
